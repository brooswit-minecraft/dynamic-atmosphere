### Changed
- MINECRAFT-436: per-player atmosphere/smoke/material network sync is now paced under an explicit, configurable total per-player operation budget (`runtime.maxSyncOperationsPerPlayerPerTick`, default 4096 chunk/cell operations, shared across all 11 sync channels -- the main grid, smoke, and each of the nine materials -- not granted independently to each) instead of sending an entire full-resync snapshot's batches in the single tick that generated them. Which channel is served first rotates every sync tick, so no channel is permanently starved by channels ahead of it.
- A snapshot too large to fit the shared budget in one tick is now delivered as a bounded, fair, atomic continuation across several ticks: queued batches that exceed the remaining budget are split (preserving `reset` only on the first piece and `snapshotEnd` only on the last) so the configured cap is actually enforced rather than bypassed on an oversized first batch; a player is still guaranteed at least one op of progress per tick even when a single indivisible unit alone exceeds the whole budget. A genuine dimension or view-distance change always supersedes any still-undelivered batches of an earlier, incomplete snapshot immediately, even mid-drain -- but the *periodic* full-resync trigger is only ever honored once the previous generation has fully drained, so it can no longer repeatedly discard its own still-in-flight snapshot before completion. A fresh plan is only ever queued once the prior generation is fully delivered (or a genuine change interrupts it), which bounds pending state to at most one generation's worth of batches regardless of elapsed ticks or how fast the live view changes -- it no longer grows unboundedly under sustained change.
- Periodic full resyncs (`runtime.fullSnapshotIntervalTicks`) are staggered per player (a stable hash of the player's UUID picks their phase), computed in units the real sync cadence can actually reach (sync-call count, not raw ticks), so every player is reachable regardless of whether the configured interval divides evenly by the sync interval.
- No wire/packet format change: `AtmosphereGridPayload`/`SmokeGridPayload`/`MaterialGridPayload` and their `reset`/`snapshotEnd` semantics are unchanged, only the tick-by-tick pacing of when already-planned batches are sent.
- A player due for a periodic full resync is no longer silently skipped when their channel happens to be busy, or never reached this tick because an earlier channel in rotation order exhausted the shared budget first: the due-ness is now latched per channel and retried every subsequent tick until that channel is actually idle and applies it, so repeated due/busy alignment (or a rotation phase-lock) can no longer prevent a periodic full resync indefinitely.
- Each chunk's visible cell list (with capacity already resolved) is now built at most once per sync tick and reused for every player whose view includes that chunk this tick, for the main grid, smoke, and each material, instead of every overlapping player independently re-reading the grid and recomputing capacity for the same cells. Scoped to one sync tick (not cached across ticks, since doing that safely for capacity-only world changes needs a signal this change deliberately does not add, to avoid touching the terrain-capacity cache files MINECRAFT-434 owns) -- freshness and correctness (including capacity-only changes) are unchanged from before.

### Added
- `runtime.maxSyncOperationsPerPlayerPerTick` server config option (default `4096`, range `1`-`1000000`): the shared per-player cap on chunk/cell operations released across all sync channels each sync tick.
- `PacedSyncQueue`, with unit and deterministic planner-to-paced-queue-to-client-cache integration coverage for: budget enforcement including splitting an oversized batch, guaranteed per-tick progress, reset-supersedes-stale-queue behavior, delta-after-snapshot ordering, eventual completion of a periodic snapshot despite an aggressively repeated periodic trigger, correct convergence of changes arriving during an unfinished snapshot, immediate supersession on a genuine dimension change mid-drain, bounded pending weight under sustained delta arrival, and disconnect/retain/clear release of queued work.
- Regression coverage proving per-player periodic full-snapshot staggering is reachable under real configured sync/full-resync intervals (including the previously-unreachable-phase case), that cross-channel budget sharing/rotation never lets total consumption exceed the configured cap, and that a pending periodic-resync latch survives both a busy channel and a channel never reached this tick.
