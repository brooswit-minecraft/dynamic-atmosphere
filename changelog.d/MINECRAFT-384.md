### Fixed
- MINECRAFT-384: atmosphere physics (transport, decay, reactions, and the deferred broken-magma lava commit) no longer advances during platform `/tick freeze`. `ForgeAtmospherePrototype.onServerTick` and `MagmaLavaGameplay.onServerTick` both run on NeoForge's `ServerTickEvent.Post`, which fires every real server tick regardless of freeze state; previously neither checked `server.tickRateManager().runsNormally()`, so a frozen server could still advance the atmosphere simulation (and commit a pending lava write) purely because wall-clock ticks kept arriving. Both now gate their dispatch on `runsNormally()`, matching vanilla's own frozen/sprint/step semantics, with no change to normal, sprinting, or single-stepped-while-frozen tick behavior.

### Added
- Regression tests proving atmosphere physics (grid transport, cadence scheduling, decay, and condensation/reaction triggers) advance strictly by simulated tick count and each grid's own really-configured `simulationIntervalTicks`, never by wall-clock time, server lag, or pause/resume gaps. Coverage drives the real `AtmosphereGrid#spread` before/after-spread hooks (the same seam `ForgeAtmospherePrototype.advanceSimulation` uses), compares full cell state (amount, capacity, lastEmissionTick, lastUpdateTick), exercises pre-due vs. due ticks, equal-tick-count runs under two real configured `simulationIntervalTicks` values, and resume-after-pause behavior. Separate tests drive `ForgeAtmospherePrototype.tick` and `MagmaLavaGameplay.tick` directly (the exact method their production `onServerTick` delegates to) to prove the new freeze gate: a frozen tick never touches the server or advances the tick counter, while a non-frozen tick still engages the real dispatch.
