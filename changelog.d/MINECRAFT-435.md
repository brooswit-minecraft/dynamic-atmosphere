### Changed
- MINECRAFT-435: bounded atmosphere producer scans around Nether/End portal discovery and the portal transfer sink, with no change to gameplay amounts, cadence, RNG semantics, or config. `PortalTransferSink`'s Nether-portal destination search now only queries the destination dimension's known-portal registry for chunks intersecting the existing 128-block search radius, instead of flattening every chunk that dimension has ever recorded a portal in; a single producer-pass call now also reuses an already-validated candidate set across source portals that resolve to the same destination chunk box. Destination resolution is now skipped entirely for a source portal with nothing to transfer, for both the Nether and End legs. The Nether/End portal section scan that `ObsidianPowderGameplay` and `PortalTransferSink` each ran independently on their respective (identically cadenced) producer passes is now a single shared scan per visited chunk per tick (`PortalChunkScanner`), and a `BlockPos` is now only allocated once a block has actually matched, never speculatively for every block a palette-gated section lets through.
- MINECRAFT-435 (review follow-up): the portal section/block scan, the glowstone scan, and the fire/smoke scan each now walk at most a configurable number of palette-gated-in chunk sections per producer call (new `runtime.maxScanSectionsPerCall`, shared `BoundedChunkScanner` engine) instead of scanning every matching section of a visited chunk synchronously; a chunk with more matching sections than the budget allows is fairly requeued (round-robin, behind other pending chunks) and resumes from where it left off on a later call, with no omitted or double-counted blocks across however many calls that takes. The per-chunk portal-transfer and End-portal-registry loops are likewise now bounded per call (new `portalTransferSink.maxSourcesPerCall`), rotating through the remainder on subsequent calls rather than looping every source/candidate in one call; the End leg additionally caches its last resolved destination and only falls back to a small rotating probe of the registry instead of flattening it on every call. A resumable scan's in-progress state is discarded when its chunk unloads or is replaced, so it can never resume against the wrong chunk instance. `AtmosphereMaterialProducer.sampleLoadedChunk` now returns whether this visit's bounded work is done, which the scheduler uses to decide whether to requeue the chunk.
